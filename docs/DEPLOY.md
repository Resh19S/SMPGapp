# Free trial deployment — Vercel + Render + Neon

**Who it's for:** giving the client a live link to try the app with demo
data. Cost ₹0. One-time setup about 15–20 minutes; afterwards every
`git push` redeploys automatically.

| Part | Service (free plan) | Address you'll get |
|---|---|---|
| Frontend (what she opens) | **Vercel** | `https://<name>.vercel.app` |
| Backend API | **Render** web service | `https://sunrise-pg-api.onrender.com` |
| Database | **Neon** PostgreSQL | a connection string (secret) |

Why three: Render's free disk is wiped on every restart, so the database
lives on Neon instead. Data survives restarts and redeploys.

**Free-plan behaviour to tell her:** the backend falls asleep after
15 minutes without visitors. The first page after a break can take
**30–60 seconds**; after that it's fast. (Optional fix in step 7.)

---

## 0. Push the code
```bash
git push origin main
```
Vercel and Render deploy from GitHub. A private repo is fine: both ask for
access to it when you sign in with GitHub.

## 1. Neon: the database (3 min)
1. https://neon.tech → **Sign up with GitHub**.
2. **Create project** (any name). Region: **AWS US East 2 (Ohio)**. It must
   match the Render region in `render.yaml` (`ohio`), because each page makes
   many database queries and they must not cross the world. If you pick
   another Neon region, change `region:` in `render.yaml` to the nearest
   Render region (e.g. Singapore → `singapore`).
3. On the project dashboard, **Connect** → turn **Connection pooling off**
   → copy the **connection string**. It looks like
   `postgresql://neondb_owner:…@ep-….us-east-2.aws.neon.tech/neondb?sslmode=require…`.
   Keep it private: it's the key to the data.

## 2. Render: the backend (5 min + ~4 min build)
1. https://render.com → **Sign up with GitHub**.
2. **New → Blueprint** → choose the `SMPGapp` repo. (Don't use Render's own
   *Postgres*: its free database is deleted after 30 days. Neon's free one isn't.) Render reads
   `render.yaml` and shows one service, `sunrise-pg-api` (free).
3. Fill in the values it asks for:

   | Key | Value |
   |---|---|
   | `DATABASE_URL` | the Neon connection string from step 1 |
   | `ALLOWED_ORIGINS` | `https://example.com` for now (fixed in step 4) |
   | `SEED_OWNER_PASSWORD` | a strong password for **owner**: her login |
   | `SEED_STAFF_PASSWORD` | password for **staff** (front desk demo) |
   | `SEED_RAVI_PASSWORD` | password for **ravi** (maintenance demo) |

   Write these passwords down. `JWT_SECRET` is generated by Render.
4. **Apply**. When the deploy shows **Live**, open
   `https://sunrise-pg-api.onrender.com/health`. It should say
   `{"status":"ok"}`. On first boot it created the tables and demo data
   (72 beds, 66 residents…).

*If Blueprint isn't offered:* **New → Web Service** → the repo, then set
Root Directory `backend`, Runtime Python, Build `pip install -r requirements.txt`,
Start command and env vars exactly as in `render.yaml` (add
`JWT_SECRET` = any 48+ random characters), Instance type **Free**.

## 3. Vercel: the frontend (3 min)
1. https://vercel.com → **Sign up with GitHub** → **Add New → Project** →
   import `SMPGapp`.
2. Vercel detects two apps (backend + frontend) and offers "Services". Ignore
   that: next to **frontend (Vite)** click **Import single project**. Root
   Directory becomes `frontend`, Framework Vite. The backend stays on Render
   (it needs a long-running server: the login lockout and session checks keep
   state in memory, and Vercel's serverless functions don't).
3. **Environment Variables:** `VITE_API_URL` = `https://sunrise-pg-api.onrender.com`
   (your Render address, **no trailing slash**). Don't set
   `VITE_SHOW_DEMO_LOGINS`.
4. **Deploy** → you get `https://<name>.vercel.app`. You can rename it under
   Settings → Domains, e.g. `sunrise-pg.vercel.app`.

## 4. Connect them (1 min)
Render → `sunrise-pg-api` → **Environment** → set `ALLOWED_ORIGINS` to the
exact Vercel address, e.g. `https://sunrise-pg.vercel.app` (https, no
trailing slash) → **Save** (it redeploys itself).

## 5. Check it yourself (5 min)
Open the Vercel link in a private window:
- [ ] Sign in as **owner** with your password → Day Book loads.
- [ ] Refresh on `/tenants`: still works (no 404).
- [ ] Record a part payment → receipt opens.
- [ ] Export to Excel downloads.
- [ ] Staff Access → sign in as **staff** in another browser → no Profit & Loss.
- [ ] Activity shows your sign-ins.

## 6. Send it to her
Share: the Vercel link, username **owner**, and the owner password. Tell
her to change it from the **Password** button after signing in. Also
mention the 30–60 s wake-up after a break, and that it's **demo data**, so
she can click anything freely.

## 7. Optional: keep it awake
https://uptimerobot.com (free) → New monitor → HTTP(s) →
`https://sunrise-pg-api.onrender.com/health` every 5 minutes. The free
plan's 750 hours/month covers one service running all month.

## Everyday operations

**Update the app:** commit and `git push`. Vercel and Render both redeploy
(Render takes ~3–4 min).

**Reset to fresh demo data** (e.g. before a second demo):
1. Neon → **SQL Editor** → run
   `DROP SCHEMA public CASCADE; CREATE SCHEMA public;`
2. Render → **Manual Deploy → Restart service**. The start command
   re-creates the tables and demo data.

**Logs:** Render → service → **Logs**. Errors are also on the Activity page
(failed sign-ins).

## Troubleshooting
| Symptom | Fix |
|---|---|
| "Could not reach the server" on sign-in | Backend is waking up: wait a minute and retry. If it persists: `VITE_API_URL` in Vercel is wrong. Fix it and **redeploy** (Vite bakes it in at build time). |
| Browser console says **CORS** | `ALLOWED_ORIGINS` on Render doesn't exactly match the Vercel address (https, no trailing slash). |
| "Too many failed attempts" | 5 wrong passwords: wait 15 minutes. |
| Render build fails on Python | Check `PYTHON_VERSION` = `3.12.7` in Render's Environment. |
| 404 when refreshing a page | `frontend/vercel.json` must be in the repo (it rewrites all paths to the app). |
